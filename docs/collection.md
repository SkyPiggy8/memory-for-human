# 把旧材料整理进来

先收一段能读懂的文字，就能开始。不要为了写回忆录，把所有聊天记录、照片和录音一次搬进来。原件留在自己的文件夹里，选出和这一章有关的部分。

## 页面能接收什么

| 入口 | 准备的内容 | 目前怎样处理 |
| --- | --- | --- |
| 问题下面的回答框 | 自己写，或家人代记录 | 保留问题和回答，分配 `A…` 编号 |
| 粘贴文字 / 选择文字文件 | UTF-8 的 `.txt`、`.md`、`.csv`、`.json`，每份最多 1 MB | 按文字读取，分配 `M…` 编号；默认不交给 AI |
| 浏览器语音输入 | 对着麦克风说话 | 需要浏览器支持，可能联网；识别后请核对 |
| 导入以前的备份 | MFH 导出的 `.mfh.json` | 恢复成新的一本，原来的作品保留 |

`.csv` 或 `.json` 文件能读作文字，不代表能自动解析各平台聊天记录。音频、图片、PDF 和手写信目前不能直接识别。录音先转写，照片先写说明，再把文字放进来。

## 录音怎么整理

先问本人愿不愿意录、给谁看、是否允许外部 AI 处理。试录几十秒，回放听清楚以后再开始。一次聊一个主题，疲倦时停下。

保留 `.m4a`、`.mp3` 或 `.wav` 原件。用自己选的转写工具生成文字，工具是否支持某种编码要看它的说明。[faster-whisper](https://github.com/SYSTRAN/faster-whisper)可作为独立工具参考，MFH 尚未集成。

转写后先核对姓名、地名、数字、方言和否定句。多人说话时，注明每句是谁说的。听不清的地方留下标记，不让 AI 猜。把整理后的短段落读给本人听，再修改。[采访方法](interviewing.md)有追问示例。

## 聊天和日记怎么整理

使用聊天工具允许的导出方式，或手动复制有关片段，保留时间、发言人和原文。文字不需要 ASR。Markdown（`.md`）就是可以用标题、列表组织的普通文字文件；不会用的话，纯文本也可以。

```text
材料名称：两人第一次旅行的聊天片段
讲述者：甲、乙（化名）
事件时间：2022 年夏，具体日期待确认
来源：双方同意选取的聊天
允许用途：家庭阅读，不公开

[原始时间] 甲：原文……
[原始时间] 乙：原文……
说明：与本章无关的私密对话已省略。
```

采访日期和事件日期分开写。不知道日期就留空或写“大约”。账号密码、会话令牌和整个平台数据库不属于写作材料。

## 照片、信件和扫描件

原图与扫描件另存。附上人物、时间、地点、发生的事，以及哪些信息还不确定。OCR 得到的文字仍要校对；照片不能证明某人的内心，也不能单靠画面猜年代。

```text
照片编号：PHOTO-002
原件：PHOTO-002_毕业合影.jpg
人物：左起第三人是讲述者（本人已确认）
时间：约 1978 年，月份不详
地点：旧校舍门口（待同学确认）
来源：家庭相册扫描
用途：家庭回忆录
```

## 原件放在哪里

放在仓库外，或仓库的 `private/` 目录中。后者已被 Git 忽略，但没有加密；发布前仍要检查文件列表。

```text
private/爷爷的一生/
├── sources.md          来源登记和允许用途
├── raw/                原始录音、照片、信件
├── transcripts/        转写与校正稿
├── interviews/         采访记录
├── chapters/           工作稿与审定稿
└── exports/            文字备份、成品和分享版
```

文件可按 `SRC-001_2026-10-13_采访_童年.m4a` 命名。文件名里的日期是采集日期，故事发生的时间写在正文里。手工原件编号 `SRC…`、`PHOTO…` 与页面的 `A…`、`M…` 不同，导入时可在材料说明里写清对应关系。[来源登记表](../templates/source-register.md)可以复制使用。

## 手工事件卡（可选）

长篇可以先用下面的记录核对先后。它是手工模板，当前应用不会自动生成或管理事件卡。

```text
事件：第一次离开家乡
时间：约 1965 年，月份待确认
人物：讲述者、母亲
地点：家乡车站，站名待确认
经过：只写已讲出的内容
原话：没有准确记录就留空
来源：SRC-001，录音 00:12:40–00:15:10
补问：那次出发是去上学还是工作？
状态：待本人确认
```

交给 AI 前，再看一遍使用范围和所选内容。让本人讲述、家人补充、历史资料各自有出处，原件有独立备份，不确定的地方仍然看得见。
