## 开始使用

Windows 下载解压后双击 `start.cmd`。macOS / Linux 需要 Node.js 22 或以上，再运行 `sh start.sh`；也可以运行 `node server.mjs`。Windows 启动器缺少运行环境时会下载并校验官方 LTS，放在项目目录里。

不会操作，可以把仓库地址和下面的话交给自己的 AI：

```text
请带我使用 Memory for Human。我不懂编程。
先读根目录 README.md 和 docs/ai-handoff.md。
你能操作这台电脑，就按仓库里的启动文件打开应用；
你只能聊天，就一步步告诉我点击哪里。
先让我选一种回忆录，讲一件小事。
没有 API Key，也可以把这里的材料交给你，写好后贴回来。
Key 由我在本机窗口填写，不放进这段聊天。
```

打开后，先看“先看怎么用”。只想写一段或试用，也可以双击 `index.html`；接 API 需要本机服务。两种入口的浏览器保存位置不同，切换前先下载备份。

有 Key 时，点击“连接我的 AI”，选择 Key 所属服务，再填进去。模型名称和地址不清楚，让自己的 AI 按官方资料帮助核对。网页聊天会员和 API 权限是两回事，连接成功与否取决于你的账号和服务。

没有 Key，就用“交给我的 AI”：选任务，决定是否附上材料，复制说明。AI 写好后，把章节文字贴回来，保存为草稿。它只能使用你提供的经历，不能替你回答人生中的空白。

<a id="materials"></a>

## 整理原始材料

先收一段能读懂的文字，就能开始。不要为了写回忆录，把所有聊天记录、照片和录音一次搬进来。原件留在自己的文件夹里，选出和这一章有关的部分。

### 页面能接收什么

| 入口 | 准备的内容 | 目前怎样处理 |
| --- | --- | --- |
| 问题下面的回答框 | 自己写，或家人代记录 | 保留问题和回答，分配 `A…` 编号 |
| 粘贴文字 / 选择文字文件 | UTF-8 的 `.txt`、`.md`、`.csv`、`.json`，每份最多 1 MB | 按文字读取，分配 `M…` 编号；默认不交给 AI |
| 浏览器语音输入 | 对着麦克风说话 | 需要浏览器支持，可能联网；识别后请核对 |
| 导入以前的备份 | MFH 导出的 `.mfh.json` | 恢复成新的一本，原来的作品保留 |

`.csv` 或 `.json` 文件能读作文字，不代表能自动解析各平台聊天记录。音频、图片、PDF 和手写信目前不能直接识别。录音先转写，照片先写说明，再把文字放进来。

### 录音怎么整理

先问本人愿不愿意录、给谁看、是否允许外部 AI 处理。试录几十秒，回放听清楚以后再开始。一次聊一个主题，疲倦时停下。

保留 `.m4a`、`.mp3` 或 `.wav` 原件。用自己选的转写工具生成文字，工具是否支持某种编码要看它的说明。[faster-whisper](https://github.com/SYSTRAN/faster-whisper)可作为独立工具参考，MFH 尚未集成。

转写后先核对姓名、地名、数字、方言和否定句。多人说话时，注明每句是谁说的。听不清的地方留下标记，不让 AI 猜。把整理后的短段落读给本人听，再修改。[采访方法](guide.md#interview)有追问示例。

### 聊天和日记怎么整理

使用聊天工具允许的导出方式，或手动复制有关片段，保留时间、发言人和原文。文字不需要 ASR。Markdown（`.md`）就是可以用标题、列表组织的普通文字文件；不会用的话，纯文本也可以。

```text
材料名称：两人第一次旅行的聊天片段
讲述者：甲、乙（化名）
事件时间：2022 年夏，具体日期待确认
来源：双方同意选取的聊天
允许用途：家庭阅读，不公开

[原始时间] 甲：原文……
[原始时间] 乙：原文……
说明：与本章无关的私密对话已省略。
```

采访日期和事件日期分开写。不知道日期就留空或写“大约”。账号密码、会话令牌和整个平台数据库不属于写作材料。

### 照片、信件和扫描件

原图与扫描件另存。附上人物、时间、地点、发生的事，以及哪些信息还不确定。OCR 得到的文字仍要校对；照片不能证明某人的内心，也不能单靠画面猜年代。

```text
照片编号：PHOTO-002
原件：PHOTO-002_毕业合影.jpg
人物：左起第三人是讲述者（本人已确认）
时间：约 1978 年，月份不详
地点：旧校舍门口（待同学确认）
来源：家庭相册扫描
用途：家庭回忆录
```

### 原件放在哪里

放在仓库外，或仓库的 `private/` 目录中。后者已被 Git 忽略，但没有加密；发布前仍要检查文件列表。

```text
private/爷爷的一生/
├── sources.md          来源登记和允许用途
├── raw/                原始录音、照片、信件
├── transcripts/        转写与校正稿
├── interviews/         采访记录
├── chapters/           工作稿与审定稿
└── exports/            文字备份、成品和分享版
```

文件可按 `SRC-001_2026-10-13_采访_童年.m4a` 命名。文件名里的日期是采集日期，故事发生的时间写在正文里。手工原件编号 `SRC…`、`PHOTO…` 与页面的 `A…`、`M…` 不同，导入时可在材料说明里写清对应关系。[来源登记表](templates.md#sources)可以复制使用。

### 手工事件卡（可选）

长篇可以先用下面的记录核对先后。它是手工模板，当前应用不会自动生成或管理事件卡。

```text
事件：第一次离开家乡
时间：约 1965 年，月份待确认
人物：讲述者、母亲
地点：家乡车站，站名待确认
经过：只写已讲出的内容
原话：没有准确记录就留空
来源：SRC-001，录音 00:12:40–00:15:10
补问：那次出发是去上学还是工作？
状态：待本人确认
```

交给 AI 前，再看一遍使用范围和所选内容。让本人讲述、家人补充、历史资料各自有出处，原件有独立备份，不确定的地方仍然看得见。

<a id="interview"></a>

## 把故事聊出来

“讲讲你的一生”太大，“那年几月几日”又常常记不清。先问一件具体的小事，等对方讲开，再接着问。问题多，是为了有得选，不是要求每个人全部回答。

### 页面里的问题库

中文、英文、西班牙语各有 156 个起始问题，顺序和主题对应。

| 故事 | 问题数 | 主要覆盖 |
| --- | --- | --- |
| 恋人 | 24 | 相识、靠近、日常、分别、变化、想留下的话 |
| 婚姻与家庭 | 24 | 共同决定、住处、家务、习惯、照顾、家庭变化 |
| 老人一生 | 48 | 家乡、童年、求学、谋生、迁居、家庭、手艺、晚年 |
| 战友 | 20 | 相识、共同日常、照应、分别、重逢、物件与原话 |
| 同事 | 20 | 初入团队、合作、分工、困难、学习、告别 |
| 同学 | 20 | 入学、校园日常、朋友、活动、毕业、重逢 |

未连接 AI 时，页面按场景顺序提问，可以换题；全部走完后会从头开始。连接后，“让 AI 接着问”依据本次选中的回答提出一个补问。程序目前不自动标记已完成的人生阶段，也不判断谁的记忆更准确。

### 围绕一件事问下去

看已有回答缺什么，挑一个容易回答的问题，不必每次走完下面的步骤。

1. **先找到场景。** “你刚才说第一次离开家，出发前在做什么？”比“离家对你意义多大”更容易开口。
2. **再补一个动作。** “到了以后，第一件事做了什么？”让事情有经过。
3. **借熟悉的东西回想。** 一条路、一张桌子、一顿饭或一件旧物，都可以成为线索。先听对方说，不把天气、颜色或情绪塞进问题里。
4. **需要时核对先后。** “这件事是在搬家前还是搬家后？”记不清年份时，允许只留下大概顺序。
5. **把解释留给本人。** “你现在怎么看那次决定？”不要问“那是不是你最幸福的一天”。
6. **最后确认写不写。** “这一段愿意放进给家人看的版本吗？”不愿公开的故事也可以只留在私人记录里。

### 一段追问示例

以下是虚构访谈，用来说明问法。

> 讲述者：刚参加工作时，我每天骑车过去。
>
> 采集者：那条上班的路，你还记得经过哪里吗？
>
> 讲述者：要过一座桥，桥头有个卖早点的。我有时在那里吃完再走。
>
> 采集者：你通常在那家吃什么？

这时已经有路、桥、早点和生活习惯。接下来可以问第一天到单位做了什么，而不是替对方补写“晨雾里怀着理想出发”。

### 给自己的 AI 的追问约定

在交接说明后补上这段话，也可以使用[完整提示词](ai-handoff.md#writing-prompts)：

```text
每轮只问一个问题，先接住我刚才讲出的具体细节。
已有答案足够清楚，就换一个还没聊过的主题。
答案很短时，问一个动作、地点、人物或旧物，不让我重讲整段。
时间模糊时允许说“大约”；只有先后影响理解时才继续核对。
不要在问题里替我给出日期、情绪或答案。
不同人记得不一样，分别记录是谁说的，别替我们选一个版本。
我说不想聊或累了，就换题或暂停。
写一章前，先指出还缺哪一两处材料；不靠编造补齐。
```

### 陪老人记录时

一次只选一个话题。先试十几分钟，对方愿意继续再聊。准备好水和一个安静的位置，录音前说明用途。停顿时给他一点时间，不急着把下一道题接上。

记下的是对方的话，不是采集者替他总结的一生。家人补充另写姓名；听不清就留空，整理后读回去请本人改。某一章材料少，可以短一点，也可以过几天拿着照片再聊。

固定问题库和 AI 追问都是采访帮手。故事的长度、说法和是否继续，由讲述者决定。

<a id="privacy"></a>

## 保存、隐私与本人审阅

先和讲述者说清楚：是否录音，哪些材料可以给 AI，作品给谁看。家人版和公开版可以不同。对方可以跳过问题、删减内容，也可以决定不成书。

### 本机保存和在线处理

项目文字保存在当前设备、当前浏览器地址的 IndexedDB 中。本机服务只监听 `127.0.0.1`，没有公开账号系统、统计或广告。

固定问题、填写、原文整理、手动编辑和导出不调用模型。点击 API 按钮时，勾选的答案和材料经本机服务发送给配置的 AI；审阅会附上当前章节。导入材料默认不勾选，答案也能取消选择。

“交给我的 AI”默认不附私人材料，选择附上后才加入选中内容。复制到在线聊天工具，就是把其中的文字交给那家服务。对方怎样保存记录，按其服务规则执行；MFH 无法代替你删除上游记录。

### Key 不属于作品

页面填写的 Key 默认只保存在本机服务本次运行的内存中，不进入浏览器项目、备份、文稿或交接包，关闭服务后需要重填。

可选的 `user-config.local.json` 是本机明文配置，由使用者另行准备。它被 Git 忽略，静态服务也不会提供这个文件。需要持久配置时，请自己保护它，别把它放进分享包。

### 备份和换设备

浏览器数据没有加密。隐私浏览、清除数据、更换浏览器、地址、端口或设备，都可能看不到原来的作品。先下载完整文字备份，再到新的位置导入；恢复会新增一本。

备份包含回答、文字材料、章节和未提交的回答，不包含原始照片和录音。原件与成品需要另存，并留独立副本。

### 本人审阅

来源编号方便核对，但模型可能漏标或引用错误。检查姓名、时间、经过、原话和他人隐私。模糊的时间保持模糊，家人补充注明是谁说的。章节修改后会重新标为草稿。

同事和战友只讲可分享的经历，不导入保密内容。真实采访、作品和私人材料放在仓库外或 `private/` 中。Git 忽略规则只是减少误提交，不是加密；公开发布前仍要检查。

<a id="production"></a>

## 打印、相册和长期保存

先做一个样品。看得清、翻得舒服、本人愿意留下，再决定印多少本或买什么设备。MFH 可以导出文字、打开打印窗口另存 PDF；图文排版、下单和相册部署目前需要自己完成。

### 出稿前

- [ ] 本人读过稿件，姓名、时间、原话与不确定项已核对。
- [ ] 知道给谁看，家人版与公开版分别准备。
- [ ] 图片有说明，使用范围已确认。
- [ ] 原件、工作稿和审定稿都有独立备份。

### 纸质回忆录

#### 准备清单（BOM）

| 要准备的东西 | 用途 |
| --- | --- |
| 审定文稿、目录、书名与署名 | 在 Word、WPS 或熟悉的工具里排版 |
| 原始照片和说明 | 按章节选择，避免只用聊天压缩图 |
| 内页 PDF、封面文件 | 规格先向店家确认 |
| 一本样品或代表页 | 包括文字、照片、封面和跨页位置 |
| 少量印制服务 | 本地图文店、数码快印店或在线书籍印制商 |

#### 怎样找店、排版和装订

1. 在地图或常用购物平台找“数码快印”“图文印刷”“少量书籍装订”。先问是否接受个人少量制作。
2. 告诉店家大概页数、份数、尺寸、照片数量和交期，索取报价、纸张及装订样品。
3. 先确认内页尺寸、出血、装订边距、封面和书脊要求，再排版。书脊厚度由页数和纸张决定，不提前猜。
4. 给老人看的稿件，先打印一页试字号。照片用原图，脸和文字离裁切线、装订缝远一点。
5. 导出 PDF，检查字体、图片、页序和空白页。内页、封面是否分文件，按店家要求。
6. 打样一本，核对错字、肤色、暗部、裁切、接缝和翻阅效果。改好再定数量、价格和配送。
7. 给店家成品文件即可，不附原始聊天和录音。

#### 可以复制给店家的话

> 我想少量印一本家庭回忆录，约［页数］页、［份数］本，有［数量］张照片。请给我尺寸、纸张和装订建议，以及打样费、成品价和制作时间。内页和封面的 PDF 要怎么准备？书脊、出血和内侧边距请按你们的工艺告诉我。

### 照片书与 AI 辅助相册

准备原图、真实说明、短章节、封面和排版工具。按事件挑代表照片，先试几页，检查裁切和双页接缝，再整理全书。

AI 可以帮忙拟标题、安排顺序和整理说明，事实仍由本人核对。旧照片修复后保留原图和修复版；生成的场景配图标为“AI 示意图”，不当作当年的照片。

### 数字相册和硬件相框

#### 先用现有设备

| 准备项 | 怎样选 |
| --- | --- |
| 闲置平板、电脑或数字相框 | 先用手头已有的 |
| 照片和故事卡 | 文字说明可排成图片 |
| 电源、支架 | 按设备说明准备 |
| 存储卡、U 盘或本地相册 | 看设备实际支持的方式 |

试播 10 张照片和 3 张故事卡，看横竖比例、字大小、顺序和轮播时间。录音播放先查设备能力，不能播放的话可以改用平板。

#### 自己组装（可选）

先查 [picframe](https://github.com/helgeerbe/picframe) 当前支持的设备，再准备电脑或树莓派、屏幕、匹配电源、存储、连接线、支架与外壳。MFH 尚未验证具体硬件组合。

步骤：启动软件 → 试照片目录 → 调方向与轮播 → 加故事卡 → 确认显示效果 → 安装外壳。先试软件和屏幕，再买齐配件。

### 家庭档案与 NAS

没有 NAS 也能保存：本机材料文件夹、独立外置存储副本、文件清单和保管说明即可。

原件与成品分别存放，用编号对应。可按三份副本、两类介质、一份异地的方式安排；[Immich 的备份说明](https://github.com/immich-app/immich)也提醒使用者重视独立备份。同步删除不等于还能恢复，至少留一份不持续连接电脑的副本。

有 NAS 再按所选工具说明部署，原件和数据库都要备份。大改或成书后保留日期版本，抽查照片能打开、录音能播放、项目能恢复。给家人留一张说明，写清在哪里、谁能读、怎样恢复。

可选工具见[工具参考](guide.md#tools)。

<a id="tools"></a>

## 可选的独立工具

第一份作品只需要文字、自己的 AI 和已有材料。录音多了再找转写工具，照片多了再考虑相册管理，不用先安装一整套服务。

以下介绍沿用 2026-10-12 查阅的官方资料。它们是独立项目，MFH 目前只提供链接，没有集成或验证具体安装。使用前按各自当前文档确认环境、备份方法和许可。

| 项目 | 适合做什么 | 怎样接入你的制作过程 |
| --- | --- | --- |
| [faster-whisper](https://github.com/SYSTRAN/faster-whisper) | 用 Whisper / CTranslate2 转写录音 | 先转文字，核对后导入 MFH；它不负责导出聊天记录 |
| [Immich](https://github.com/immich-app/immich) | 自托管照片与视频管理 | 存原图和相册素材；需要自己维护和备份 |
| [picframe](https://github.com/helgeerbe/picframe) | 在受支持的树莓派设备上展示照片 | 先做照片和故事卡，再按其文档搭相框 |
| [Paperless-ngx](https://github.com/paperless-ngx/paperless-ngx) | 扫描、索引与归档文档 | 整理信件、扫描件和成稿；原件仍需另存 |
