**把你记得的生活，留成一本能继续写、能交给家人的回忆录。**

我想做这件事，是因为有些故事只有一个人记得。家里的老人讲过，却没人记下来；两个人走过很多年，照片还在，当时的小事已经说不清了。Memory for Human（MFH）让 AI 帮忙提问和整理，让这些经历有地方留下，也让家人以后还能接着补。

MFH v0.2 已有**可在本机使用的回忆录工具**。界面、采访问题、入门解释和 AI 交接说明支持中文、英文、西班牙语。API Key 使用者自行提供；没有 Key，也可以整理材料并交给平时使用的 AI。

## 没用过这类工具，也能开始

把它想成一个会帮忙整理的小本子。你写一段话、回答一个问题，或者把家人的话记下来。AI 只能依据这些内容，帮你写得连贯些。你检查后，留下文字，或者打印成书。

你只需要会两件事中的一种：**在页面里填自己的 API Key**，或**把“交给我的 AI”里的说明复制给平时使用的 AI**。不会操作的老人可以只负责讲，家人负责填写与核对。

页面里的「先看怎么用」会用日常语言解释用途、操作、Key、没有 Key 时的办法和资料去向。连接后，还可以让自己的 AI 再解释一次。

## 开始使用

### Windows：双击一个文件

1. 下载仓库并解压。
2. 双击 **`start.cmd`**。第一次若没有合适的运行环境，它会从 Node.js 官方网站下载并校验 LTS 版本，只放在本项目目录，不需要管理员安装。
3. 浏览器打开本地页面。保持启动窗口运行；关闭窗口即可停止服务。
4. 右上角选语言。点击「开始我的回忆录」，或先试一个明确标为虚构的示例。

本机默认地址为 `http://127.0.0.1:4317`。首次准备运行环境需要联网；以后填写、整理与备份可以不联网。下载失败时，把 [AI 交接说明](docs/ai-handoff.md#handoff)交给能操作电脑的 AI，让它协助。

### macOS / Linux

让自己的 AI 按 [AI 交接说明](docs/ai-handoff.md#handoff)准备 Node.js 22 或以上，再运行 `sh start.sh`。熟悉命令行的人也可直接运行：

```sh
node server.mjs
```

只想先看看或填写？也可双击 `index.html`。**直接打开文件时不提供 API 连接**，但可以填写、导入文字、编辑、导出和备份。文件模式与本地网页是不同的浏览器保存位置，切换前先下载备份，再导入。

## 先写好一章

1. **选一种回忆录。** 取名字，写明讲述者、读者，决定先写一章还是慢慢写长篇。
2. **把故事讲出来。** 一次一个问题。直接输入、使用支持的浏览器语音输入，或导入文字材料。答案可以修改。
3. **整理成章节。** 连接 AI 写一章；也可把已有文字放在一起，或贴入自己 AI 写好的章节。逐章修改、检查、标为本人已审阅。
4. **保存与制作。** 下载完整文字备份、Markdown 文稿，或打开打印窗口另存为 PDF。按制作清单打样、装订与保存。

填写内容保存在这台设备的浏览器中。可以新建多本、切换、恢复备份。**浏览器存储不是唯一备份**，重要内容请下载项目文件并保留独立副本。

## 用自己的 AI

| 方式 | 你需要做什么 | 能做什么 |
| --- | --- | --- |
| 填 API Key | 选 Key 所属服务，在本地窗口填写 | 连接测试、继续采访、逐章写作、检查稿件、解释用法 |
| 平时使用的 AI | 复制交接说明，选择是否附上材料，再交给自己的 AI | 手动继续采访、写作与审阅，把结果贴回本项目 |
| 能操作电脑的 AI | 交给它仓库与 [AI 交接说明](docs/ai-handoff.md#handoff) | 按实际文件启动、配置，教你如何操作 |
| 本地模型 | 在其他选项中填本机兼容接口和模型名称 | 通过本地接口处理文字；运行环境自行准备 |

界面提供 OpenAI、DeepSeek、Claude、豆包及其他兼容服务的配置。默认值可以改；**Key 的权限、余额和模型可用性以你的账号为准**。预设接口已按官方资料实现并用模拟响应测试，尚未用使用者的真实 Key 做服务商逐一实测。[接口依据与验证范围](docs/technical.md#api)

网页版聊天账号与 API 是两个入口。不会配置模型名称或服务地址，可以让自己的 AI 按交接说明协助；不要把真实 Key 写进聊天、作品、交接包或公共仓库。Key 默认只留在本机服务本次运行的内存里。

## 六类故事，用不同的结构

以下为中文写作参考。英文、西班牙语根据实际材料调整，不强制对应字数，也不靠重复或虚构凑长度。

| 回忆录 | 建议结构 | 中文篇幅参考 |
| --- | --- | --- |
| [恋人](docs/templates.md#lovers) | 相遇 → 靠近 → 日常 → 转折 → 想对你说 | 3,000–15,000 字 |
| [婚姻与家庭](docs/templates.md#marriage) | 相识 → 共同决定 → 婚礼 → 家庭 → 一起成长 | 8,000–30,000 字 |
| [老人一生](docs/templates.md#life) | 童年 → 求学 → 工作 → 家庭 → 转折 → 晚年 → 后人 | 30,000–80,000 字，逐章完成 |
| [战友](docs/templates.md#comrades) | 初见 → 共同生活 → 难忘经历 → 分别 → 后来的联系 | 8,000–30,000 字 |
| [同事](docs/templates.md#colleagues) | 加入 → 合作 → 关键时刻 → 成长 → 告别 | 5,000–20,000 字 |
| [同学](docs/templates.md#classmates) | 入学 → 日常 → 集体时刻 → 毕业 → 再相逢 | 5,000–20,000 字 |

长篇可以分成约 10–16 章，每次只聊一个主题，累了就停。先写一章给本人读，再决定继续。篇幅是参考，材料少就短一点，不靠重复和编造凑字数。

三种语言各有 **156 个起始问题**：恋人 24、婚姻 24、一生 48、战友 20、同事 20、同学 20。AI 追问会先接着已讲出的动作、人物、地点或旧物，场景清楚后再换主题。一次一个问题，可以跳过。[怎样把故事聊出来](docs/guide.md#interview)

## 材料怎样交进来

- **直接填写：** 在问题下面回答，家人可以代记录。
- **已有文字：** 导入 UTF-8 `.txt`、`.md`、`.csv`、`.json`，每份不超过 1 MB。当前按文字读取，不承诺每个平台聊天格式自动适配。
- **录音：** 先用自己的工具转写并校对，再导入文字。页面的语音输入依赖浏览器支持，可能联网；不是上传音频文件的 ASR。
- **照片：** 把人物、时间、地点、故事写成说明。保留照片原件；当前不识别图片、PDF 或手写信。
- **完整备份：** 从「下载完整文字备份」得到 `.mfh.json`，导入会创建一本新回忆录，不覆盖原来那本。

新导入的材料默认**不交给 AI**，可以逐份勾选。答案也可按章取消或勾选。AI 处理时使用勾选的答案与材料，以及任务所需的章节。材料过多会提示拆分，不悄悄截掉整个人生。[详细采集指南](docs/guide.md#materials)

## 写过以后，还要本人核对

AI 整理已有经历、提问和润色，不能替人填造事实。工作稿保留 `[A1]`（采访答案）、`[M1]`（勾选材料）等来源标记；检查疑点后由本人决定最终版本。修改章节会将其重新标为草稿。

本地页面不等于所有处理都离线。调用在线 AI 或把交接包粘贴给在线工具，所选文字就会交给该服务。采访、聊天和照片的采集与分享范围请先取得相关人同意。[隐私说明](docs/guide.md#privacy)

完整文字备份包含本项目的回答、导入文字、草稿与未提交的回答，不包含 API Key、原始照片和音频文件。原件请另行保存。

## 打印、相册和长期保存

| 成品 | 最简单的路径 |
| --- | --- |
| 纸质回忆录 | 审阅 → 下载文稿 → 向图文店问规格 → 排版成 PDF → 打样一本 → 校对与装订 |
| 照片书 | 选原图 → 附真实说明 → 排版 → 检查裁切 → 打样 |
| 数字相册 / 相框 | 先在闲置平板上展示照片与故事卡，再决定是否买专用硬件 |
| 家庭档案 / NAS | 本机资料 + 独立副本；有需要再用 NAS，并做恢复检查 |

[制作清单](docs/guide.md#production)包括 BOM、询价话术、打印与装订步骤。[延伸工具](docs/guide.md#tools)链接语音转写、照片管理、硬件相框与文档归档项目，当前没有自动集成它们。

## AI 怎么接手这个项目

页面里的「交给我的 AI」会按任务与语言生成说明。默认不附私人材料；勾选后才加入已保存答案与选中材料。可以复制或下载 Markdown，再把 AI 的普通章节文字或约定 JSON 粘贴回来。

仓库同时提供 [中文](docs/ai-handoff.md#handoff)、[英文](docs/translations/AI-HANDOFF.en.md)、[西班牙语](docs/translations/AI-HANDOFF.es.md)交接文档，供能读取文件或操作电脑的 AI 使用。[AGENTS.md](AGENTS.md)说明真实文件、启动方式、验证要求与能力边界。

## MFH 的技术工作

项目的工作集中在四件事：**来源可追溯、模型解耦、人工审阅、进度可恢复**。答案和材料各有稳定编号，写作只使用选中的部分；自己的聊天 AI 和 API 共用任务规则，结果回到同一本作品；章节修改后重新审阅；恢复备份新增一本，避免覆盖。

前端是无需构建的原生网页，本机服务使用 Node.js 内置模块，密钥与作品分开。六类关系、三语操作、家人代记录和制作清单，组成从采访到成品的完整流程。[技术设计](docs/technical.md#architecture)解释数据结构、请求范围、确认状态和长篇限制。

StorySage 重点研究多智能体采访与写作，memoir 采用工具调用和结构化时间线。MFH 把重点放在普通家庭怎样用自己的 AI 开始、怎样保留材料和带走作品。来源保留与本人审阅也见于其他项目，本项目的差异来自这些设计的组合。[参考项目与具体区别](docs/technical.md#related-work)
